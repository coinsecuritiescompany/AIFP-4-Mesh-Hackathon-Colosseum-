# Локальный MVP AIFP-4 Mesh

## Запуск

Нужен Node.js 24 и npm. Docker для этого варианта не нужен.

```bash
npm ci
npm run ci
npm run demo:smoke
npm start
```

Дождитесь `READY`. Откройте http://127.0.0.1:4044/.
Нажмите **API key**, вставьте ключ, который launcher напечатал после `READY`, затем **Connect**.
Всё выполняется на вашем компьютере. Здесь нет удалённого хостинга.

Launcher запускает четыре отдельных процесса. Только C исполняет платежи.
Данные и ключи узлов сохраняются в `.data/local-demo`, API-ключ — в `.env`.
После обычной остановки и нового `npm start` история сохраняется.
`npm run demo:smoke` использует отдельные временные данные и другие порты, не останавливает вашу демосеть.

`npm run sandbox` запускает прежний одиночный sandbox. Для видео используйте `npm start`.

## Видео на 2–3 минуты

1. Откройте **Mesh network**. Покажите четыре узла и TCP/libp2p.
2. **Create payment**: USDC, 250 minor units (= 2.50 mock USDC), beneficiary `ai-data-api`.
3. Создайте intent. До нажатия **Send through Mesh** платёж остаётся `AUTHORIZED`.
4. Нажмите **Send through Mesh**. Дождитесь `SETTLED`, путь A→B→C и `VERIFIED`.
5. В терминале launcher введите `stop b`. Дождитесь обновления topology.
6. Создайте и выполните второй платёж. Покажите путь A→D→C и новую квитанцию.
7. Введите `stop c`. Создайте и выполните третий платёж: он останется `QUEUED_FOR_MESH`.
8. Введите `start c`. Дождитесь автоматического `SETTLED` и `VERIFIED`.
9. Покажите **Transactions**. В конце введите `start b`, затем `quit`.

Интерфейс обновляет статусы и topology каждые 3 секунды. Формы ввода не перерисовываются автоматически.
Возвращение узла может занять несколько секунд: нужно восстановить соединения и объявления маршрутов.

## Что можно говорить в видео

«Четыре независимых узла передают подписанный платёжный intent через TCP и libp2p.
При отказе реле выбирается другой путь. Если settlement-узел недоступен, intent хранится локально.
После восстановления связи возвращается подписанная квитанция. В этом видео расчёт выполняется в mock USDC».

Mock USDC не является настоящим переводом USDC в Solana. Для доказательства Solana нужен отдельный Devnet-сценарий ниже.

## Solana Devnet

Перед записью on-chain видео потребуется отдельный кошелёк с тестовым SOL.
В локальную `.env` добавьте `SOLANA_PAYER_SECRET_JSON` — JSON-массив 64 байт этого Devnet-кошелька.
Не используйте основной кошелёк. Секрет передаётся только узлу C, в интерфейс он не попадает.
Перезапустите launcher, выберите SOL, укажите реальный адрес получателя и сумму в lamports.
Создайте intent, нажмите Execute и дождитесь ссылки на Solana Explorer с `cluster=devnet`.
Ссылка появляется после подтверждения транзакции. 1 SOL = 1 000 000 000 lamports.

Реальную Devnet-транзакцию при подготовке этой версии не запускали: оплаченный тестовым SOL кошелёк не был предоставлен.
Тесты Solana-адаптера проверяют инструкции transfer/memo, ожидание подтверждения и блокировку повторного исполнения при неизвестном результате; они не заменяют on-chain proof.

## Ограничения

Это проверенный программный MVP для локального тестирования. Production с настоящими деньгами не подтверждён.
Есть TOFU при первом знакомстве с peer, локальные хранилища, один settlement-узел и нет согласования лимитов между несколькими settlement-узлами.
TCP передаёт данные без шифрования. libp2p использует Noise.
Аппаратные Bluetooth/LoRa/satellite, BPv7/COSE/BPSec и fiat/cards отсутствуют.
Поле agent passport — идентификатор демо; интеграции с внешним Agent Passport нет.

Для Colosseum сначала покажите работающее демо и явно обозначьте mock rail.
Перед подачей Solana-проекта запишите отдельный подтверждённый Devnet-платёж и проверьте требования выбранного соревнования.
Заявку и видео эта версия автоматически не отправляет.

## Если не запускается

- Версия Node ниже 22.13: установите Node 24; нужен встроенный `node:sqlite`.
- Заняты порты: остановите старый launcher. Либо измените `AIFP4_PORT` в `.env`, например на `5044`. Используются base…base+3, base+100…103, base+200…203.
- Ошибка авторизации: введите API key из launcher в интерфейс.
- Нет READY: сообщение содержит последние строки лога узла. Сначала выполните `npm run ci` и `npm run demo:smoke`.
- Очередь не завершилась: проверьте `status` в терминале, `start c`, затем topology и историю событий.
- Ошибка/неизвестный результат Devnet: проверьте кошелёк и сеть перед повторной попыткой; состояние `executing` блокирует повторное списание.

Удаление `.data/local-demo` уничтожит локальную историю и идентичности. Для повторной записи это обычно не требуется.
