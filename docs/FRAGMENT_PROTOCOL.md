# Fragment delivery

TCP and libp2p encode the same bounded CBOR fragment format. Each frame identifies the wire message, index/count, source envelope hash, fragment hash and expiry. A receiver persists partial reassembly, rejects changed duplicates or corrupt chunks, and releases bytes to the Mesh verifier only after every fragment arrives and the reconstructed hash matches. The maximum is 512 fragments and 64 KiB per envelope. Fragments are transport bytes, not financial authorization.

The libp2p Noise/Yamux adapter additionally supports a transport-level status request bound to the wire message ID and source envelope hash. The receiver reports missing indexes from its persisted reassembler; the sender resends only those indexes, with a bounded retry count. Its outgoing connection is checked against the peer ID from the signed advertisement. The status is authenticated by the Noise connection, but it is **not** the signed AIFP `HOP_ACCEPTED`: the latter follows full envelope verification and durable Mesh acceptance. The test drops one frame from a transfer of more than 50 fragments and observes exactly that index retransmitted.

TCP still retries an entire envelope when a fragment is lost. Outgoing fragments are not persisted independently; a sender crash falls back to coordinator whole-envelope retry with a fresh wire message. libp2p fragment status requires an immediate reverse channel and therefore is not usable unchanged on delayed or one-way radio/satellite links. A future convergence adapter must durably journal outgoing fragments and carry signed or authenticated status asynchronously, possibly over another path. Neither RFC 9171 BPv7 interoperability nor physical bearer support is claimed.
