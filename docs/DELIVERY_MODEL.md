# Asynchronous Mesh delivery

The origin signs a payment intent once. Its `intentId` and `intentHash` are the financial idempotency key. A `bundleId` identifies one logical Mesh delivery (payment, receipt, or ACK). A `hopDeliveryId` identifies the sender's responsibility to one next-hop peer. Each retry creates a newly signed wire `messageId`; the hop record retains recent message IDs so a delayed signed acceptance remains valid. A transport `submissionId` only identifies a local adapter attempt. TCP fragment IDs identify frames, not payments. None of these delivery IDs authorize a second settlement.

The origin commits a queued bundle to its own SQLite WAL database before submitting transport bytes. Every forwarding node authenticates its configured neighbor, verifies the signed envelope, protected origin intent, path and expiry, then atomically stores the complete bundle, inbox record and replay marker. It signs a `HOP_ACCEPTED` bound to bundle ID, hop ID, accepted wire message ID, bundle hash, and both nodes. This ACK itself travels as a Mesh bundle and may take a different route. The sender marks that hop accepted only after signature verification against its pinned peer key. A transport's `ACCEPTED_LOCAL` is neither remote acceptance nor settlement.

Receipt delivery uses the same independent queue and graph planner. The origin verifies the settlement node signature and intent hash before marking the payment settled. A receipt can return via another route. Repeated deliveries remain possible; the settlement node's persistent intent execution record is authoritative. External execution with an uncertain outcome remains locked, pending explicit reconciliation.

The current coordinator retries whole signed envelopes with bounded backoff. It retains accepted bundles and replay markers across restart. SQLite transactions cover local bundle/hop records and the inbound bundle/inbox/replay group. Payment store, node identity and TCP/libp2p partial fragments still reside in separate files, so there is no single transaction across financial execution and Mesh custody. Peer discovery uses synchronous control messages. TCP and libp2p use a common bounded CBOR fragment codec. libp2p can selectively resend missing frames while its Noise connection is available; outgoing fragments are not yet durably journaled and TCP still retries the whole envelope. This is a disruption-tolerant application protocol, not RFC 9171 BPv7 or RFC 9172 BPSec.

Admission caps active bundles at 64 total, with separate limits of 32 payments, 16 receipts and 16 ACKs. Each origin may hold 16 active bundles of each kind. The coordinator processes receipts before ACKs and payments. A full queue rejects inbound payment custody before writing a replay marker or issuing a signed ACK; transport submission alone cannot override that decision.
